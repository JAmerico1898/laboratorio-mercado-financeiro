Módulo S8 — Gestão de Crédito

Novo módulo do Laboratório de Tesouraria de Empresas: quatro cenários sobre gestão de carteira de crédito bancária, no mesmo padrão dos módulos S6/S7 e do cenário-referência “Indústria Alfa”. Todos os casos rodam sobre um único motor — perda esperada PE = PD × LGD × EAD. O aluno escolhe opções, o app valida e mostra a memória de cálculo; tudo que resolve a etapa está em KeyFacts; o volumoso (dados da operação, cenários, carteiras) fica numa caixa ocultável.

1. Visão geral do módulo

O módulo Gestão de Crédito cobre o ciclo da carteira de crédito por quatro lentes. Os casos isolam, um a um: diferenciação de risco no nível do empréstimo, definição de apetite a partir do cenário macro, controle de dano na recessão e o risco de concentração no nível do portfólio.

Duas amarrações pedagógicas a manter no texto: S8.1 ↔ S8.4 (a perda esperada média vs. o que ela esconde — a cauda/concentração) e S8.2 → S8.3 (definir apetite antes, controlar o dano durante).

2. Motor único, premissas e diferenças vs. S6/S7

Os quatro cenários compartilham uma única fórmula de perda esperada:

PE = PD × LGD × EAD  —  perda esperada = probabilidade de inadimplência (PD) × perda dado o default (LGD) × exposição no momento do default (EAD).

Glossário (introduzir no contexto/KeyFacts, não em chip): PD = probabilidade de default · LGD = loss given default (perda dado o default; colateral reduz a LGD) · EAD = exposure at default · PE = perda esperada · NPL = crédito inadimplente (90+ dias) · cobertura = provisão ÷ NPL.

Diferenças explícitas em relação aos módulos anteriores:

  1. Sem chip global. Diferente do S6 (chip de regra IB ≥ 10,5%), o S8 não tem faixa fixa no topo. A fórmula e os termos são apresentados no contexto e nos KeyFacts de cada cenário. Não implementar GlobalRuleChip.
  2. Caixa ocultável com rótulo adaptável por cenário (campo detailBoxLabel): “DADOS DA OPERAÇÃO” (S8.1), “CENÁRIOS MACRO” (S8.2), “CARTEIRA E PROVISÕES” (S8.3), “COMPARATIVO DE CARTEIRAS” (S8.4).
Rigor normativo: o provisionamento por perda esperada segue o espírito da Res. CMN 4.966 (vigente desde jan/2025, substituiu a 2.682), incluindo a lógica de estágios e de aumento significativo de risco de crédito. Os dispositivos específicos (estágios 1/2/3, gatilhos) devem ser marcados “verificar” antes de publicar. PD, LGD, CDI e taxas de inadimplência são premissas de aula.

4. Máquina de estados (jornada do cenário)

card → contexto → etapas (3, sequenciais) → encruzilhada → resultado(caminho) → reflexão → conclusão
  1. contexto — narrativa com termos destacados + KeyFacts + caixa ocultável (rótulo do cenário).
  2. etapas — 3 múltiplas escolhas com revelação progressiva: a Etapa N+1 só abre após acerto da N. Cada opção exibe memória de cálculo (verde se certa, vermelha se errada). Erro não pontua e permite nova tentativa. Pontua na 1ª seleção correta.
  3. encruzilhada — 3 cards de decisão (A/B/C); não há “certo”. 0 pontos.
  4. resultado(caminho) — headline + caption + tiles de variação (deltas) + explicação do trade-off.
  5. reflexão — 1 MC sobre o risco residual (25 pts).
  6. conclusão — “PONTUAÇÃO FINAL X / 85” + “Tentar outro cenário” / “Finalizar e voltar”.

Barra de progresso = 3 etapas. Transição 0/85 → 60/85 → 85/85.

6. Modelo de dados (TypeScript)

Mesmos tipos do S7, com o acréscimo de detailBoxLabel (rótulo adaptável da caixa ocultável).

interface KeyFact { label: string; value: string; tone?: "default" | "positive" | "warning"; }

interface DetailTable {
  id: string; title: string; columns: string[];
  rows: { label: string; values: string[]; emphasis?: boolean }[];
  note?: string;
}

interface Option { id: string; text: string; correct: boolean; feedback: string; } // feedback = memória de cálculo
interface Etapa { id: string; label: string; prompt: string; options: Option[]; points: number; } // 4 opções, 1 correta, 20 pts
interface DeltaMetric { label: string; value: string; tone: "positive" | "negative" | "neutral" | "risk"; }
interface Resultado { headline: string; caption: string; metrics: DeltaMetric[]; explanation: string; }
interface Branch { id: "A" | "B" | "C"; title: string; summary: string; resultado: Resultado; }
interface Reflexao { prompt: string; options: Option[]; points: number; } // 25

interface Scenario {
  id: string; code: string; order: number;
  title: string; protagonist: string;
  difficulty: "intermediario" | "avancado"; estMinutes: number;
  blurb: string; archetype: string; context: string;
  keyFacts: KeyFact[];
  detailBoxLabel: string;                     // rótulo adaptável: "Dados da operação", "Cenários macro"...
  details: DetailTable[];
  etapas: Etapa[];                            // 3
  encruzilhada: { prompt: string; branches: Branch[] };
  reflexao: Reflexao;
  maxScore: number;                           // 85
}

7. Pontuação e persistência

  • 3 etapas × 20 + reflexão 25 = 85. Encruzilhada = decisão (0 pts).
  • Pontua na 1ª seleção correta; erros não descontam nem readicionam.
  • Estado por cenário: { phase, currentEtapaIndex, answers, chosenBranch, score, completed }; localStorage por scenarioId.
  • Progresso do módulo (x/4 concluídos) deriva de completed.

9. Convenções de conteúdo

  • Autossuficiência: tudo que resolve as etapas está nos KeyFacts; tabelas volumosas vão na caixa ocultável (rótulo do cenário).
  • Memória de cálculo SEMPRE com a conta (fórmula + números). No acerto, reforça o conceito; no erro, aponta o equívoco específico. Cada opção incorreta tem sua memória de erro.
  • Padrão E1 → E2 → E3: E1 = leitura/medida; E2 = mecanismo; E3 = cálculo-síntese.
  • Unidades: S8.1 no nível do empréstimo usa R$ mil; S8.2–S8.4 no nível de portfólio usam R$ mi. Deixar a unidade explícita em cada KeyFact/tabela.
  • Introduzir PD/LGD/EAD/PE/NPL no contexto na primeira aparição (sem chip de glossário fixo).

10. Checklist de QA

  • Os KeyFacts bastam para resolver as etapas? O resto está na caixa ocultável?
  • Cada etapa tem 4 opções plausíveis, 1 correta e memória com a conta (inclusive nas erradas)?
  • Os 3 caminhos da encruzilhada divergem (deltas e trade-offs distintos)?
  • A pontuação soma 85 (3×20 + 25)? Transição 0 → 60 → 85 confere?
  • Sem GlobalRuleChip? DetailBox usando o detailBoxLabel de cada cenário?
  • PE = PD × LGD × EAD consistente em todos os cálculos? Unidades (mil/mi) corretas por cenário?
  • Specs de provisionamento (4.966/estágios) marcadas “verificar”?
  • Progressão/mix de dificuldade (S8.1/S8.3 intermediário, S8.2/S8.4 avançado)?

S8.1 · Crédito Alfa · Intermediário · 20 min

Alto risco × baixo risco: preço e gestão diferenciados

Blurb (card): Dois pedidos de empréstimo de mesmo valor, perfis de risco opostos. Como o risco muda a perda esperada, o preço e a forma de gerir cada um?

Pergunta-chave: como o perfil de risco muda preço, provisão e intensidade de gestão de um empréstimo?

Contexto (narrativa)

Você é analista de crédito do Crédito Alfa. Chegam dois pedidos de R$ 1.000 mil cada. O Empréstimo A é de um tomador sólido (PD baixa, com garantia); o B é de um tomador frágil (PD alta, sem garantia). A perda esperada de cada um é PE = PD × LGD × EAD — onde PD é a probabilidade de inadimplência, LGD a perda dado o default (a garantia reduz a LGD) e EAD a exposição. Sua tarefa: medir a PE, entender por que alto risco exige preço e gestão diferentes, e precificar cada operação.

Etapa 1 Leitura — perda esperada (20 pts)

Prompt: Qual a perda esperada (PE) do Empréstimo B?

A) R$ 40 mil ✓ Correto
PE = PD × LGD × EAD = 8% × 50% × 1.000 = R$ 40 mil (PE% = 4,0% sobre a EAD).
B) R$ 80 mil ✗
Erro: esqueceu a LGD (usou PD × EAD). PE = 8% × 50% × 1.000 = 40 (não 8% × 1.000 = 80).
C) R$ 5 mil ✗
Erro: usou a PD do Empréstimo A (1%). Com a PD de B (8%): 8% × 50% × 1.000 = 40.
D) R$ 3 mil ✗
Erro: essa é a PE do Empréstimo A (1% × 30% × 1.000). A de B é 40.

Etapa 2 Mecanismo — por que preço E gestão diferentes (20 pts)

Prompt: Por que um empréstimo de alto risco exige preço maior e gestão mais intensa?

A) O preço cobre a perda esperada (a média); a gestão (colateral, covenants, monitoramento) trata a perda inesperada (a cauda). PD e LGD são alavancas distintas. ✓ Correto
Precificar a PE protege a média; o desvio acima dela (perda inesperada) é gerido com mitigantes e capital. O colateral ataca a LGD; o score/limite ataca a PD.
B) Basta cobrar mais; o preço resolve todo o risco. ✗
Erro: o preço cobre só a perda esperada (média); a perda inesperada (cauda) exige capital e gestão.
C) Alto risco se gerencia só com mais provisão, não com preço. ✗
Erro: a provisão cobre a PE, mas o preço também precisa remunerar capital e custos; e a gestão trata a cauda.
D) Colateral aumenta a PD. ✗
Erro: o colateral reduz a LGD (perda dado o default), não a PD. São alavancas diferentes.

Etapa 3 Síntese — taxa mínima (20 pts)

Prompt: Quais as taxas mínimas dos Empréstimos A e B?

A) A = 14,3%; B = 18,0% ✓ Correto
Taxa = funding + PE% + opex + margem. A = 11 + 0,3 + 1 + 2 = 14,3%; B = 11 + 4,0 + 1 + 2 = 18,0%. O wedge de 3,7 p.p. é puro risco (ΔPE%).
B) A = 14,0%; B = 14,0% (igual) ✗
Erro: ignorou a diferença de PE%. O risco entra via PE% (0,3% vs 4,0%): A = 14,3%, B = 18,0%.
C) A = 13,3%; B = 17,0% ✗
Erro: esqueceu o opex (1%). A = 14,3%, B = 18,0%.
D) A = 12,3%; B = 16,0% ✗
Erro: faltou a margem-alvo (2%). A = 14,3%, B = 18,0%.

Reflexão — risco residual (25 pts)

Prompt: Mesmo precificando a PE corretamente, qual risco residual permanece?

A) A PE é a perda média, já no preço; o perigo real é a perda inesperada (cauda), coberta por capital e monitoramento — não pelo preço. ✓ Correto
Precificar a média não protege de um default acima do esperado; é para isso que existem capital, colateral e acompanhamento.
B) Nenhum: se a PE está no preço, o empréstimo está coberto. ✗
Erro: o preço cobre a média; a perda inesperada (cauda) não.
C) O risco residual é só o funding subir. ✗
Erro: o risco central é a perda inesperada do crédito, não o custo de funding.
D) Colateral elimina toda a perda. ✗
Erro: o colateral reduz a LGD, não zera a perda (execução imperfeita, garantia desvaloriza no estresse).

Cenário S8.2 — Comitê de Crédito Avançado

S8.2 · Comitê de Crédito · Avançado · 24 min

Cenários macroeconômicos e apetite de risco

Blurb (card): O comitê precisa definir quanto originar no segmento-alvo no próximo ano. A PD depende do cenário macro. Quanto a visão forward muda o apetite?

Etapa 1 Leitura — PD por cenário (20 pts)

Prompt: Qual a PD em cada cenário?

A) Base 3%; adverso 6% ✓ Correto
Leitura direta dos KeyFacts: cenário base 3%, cenário adverso (recessão) 6%.
B) Base 6%; adverso 3% ✗
Erro: invertido. O cenário adverso tem a PD maior (6%); o base, 3%.
C) 4,5% nos dois (média simples) ✗
Erro: são duas PDs distintas (3% e 6%); a média simples ignora as probabilidades.
D) 9% (soma dos cenários) ✗
Erro: PDs não se somam; cada cenário tem a sua (3% e 6%).

Etapa 2 Mecanismo — por que apetite forward (20 pts)

Prompt: Sobre qual PD o apetite deve ser fixado, e por quê?

A) Sobre a PD ponderada pela probabilidade dos cenários — porque o crédito originado hoje viverá o futuro, não o presente benigno. ✓ Correto
Usar só o cenário base superdimensiona o apetite. A PD relevante é a esperada (ponderada), pois a carteira nova atravessa o cenário futuro.
B) Sobre o melhor cenário (base), para não perder negócios. ✗
Erro: isso superdimensiona o apetite e ignora o risco do cenário adverso.
C) Sobre a PD atual realizada, não cenários. ✗
Erro: a PD realizada é olhar para trás; o apetite é forward — a carteira nova viverá o futuro.
D) Cenários não afetam o apetite, só o preço. ✗
Erro: a PD esperada governa tanto preço quanto volume/apetite.

Etapa 3 Síntese — PD ponderada e apetite (20 pts)

Prompt: Qual a PD ponderada e o apetite (EAD máximo) correspondente?

A) PD 4,2%; apetite R$ 10.000 mi ✓ Correto
PD = 0,6×3% + 0,4×6% = 4,2%. Apetite = orçamento ÷ (PD × LGD) = 189 / (0,042 × 0,45) = R$ 10.000 mi (vs 14.000 no base).
B) PD 4,5%; apetite R$ 9.333 mi ✗
Erro: usou média simples (4,5%), não a ponderada pelas probabilidades (4,2%).
C) PD 4,2%; apetite R$ 14.000 mi ✗
Erro: aplicou a PD ponderada mas dividiu pela PD base. Apetite = 189 / (0,042 × 0,45) = 10.000.
D) PD 4,2%; apetite R$ 4.500 mi ✗
Erro: esqueceu a LGD no denominador (189/0,042). Apetite = 189 / (0,042 × 0,45) = 10.000.

D) Cenários eliminam o risco da carteira. ✗
Erro: ajudam a calibrar o apetite, não eliminam o risco realizado.

Etapa 1 Leitura — crédito problemático (20 pts)

Prompt: De quanto é o aumento do estoque de NPL com a recessão?

A) +R$ 1.000 mi ✓ Correto
NPL antes = 4% × 20.000 = 800; na recessão = 9% × 20.000 = 1.800; aumento = 1.800 − 800 = R$ 1.000 mi.
B) +R$ 1.800 mi ✗
Erro: confundiu o estoque pós-recessão (1.800) com o aumento. Aumento = 1.800 − 800 = 1.000.
C) +R$ 500 mi ✗
Erro: usou metade da variação. Δ = (9% − 4%) × 20.000 = 5% × 20.000 = 1.000.
D) +R$ 2.600 mi ✗
Erro: somou as taxas (9% + 4%). Usar a diferença (5 p.p.): Δ = 1.000.

Etapa 2 Mecanismo — por que a provisão dispara (20 pts)

Prompt: Por que a recessão dispara a provisão?

A) Sobe a PD (mais defaults) e a LGD (garantias valem menos) → a perda esperada salta → a PDD bate no resultado e no capital. ✓ Correto
A recessão move as duas alavancas da PE: mais inadimplência (PD) e menor recuperação das garantias (LGD).
B) Só a PD muda; a LGD é fixa. ✗
Erro: na recessão o valor das garantias cai, elevando também a LGD.
C) A provisão sobe porque a carteira cresceu. ✗
Erro: a carteira é estável (20.000); o que sobe é a inadimplência, não o tamanho.
D) A provisão não afeta o capital. ✗
Erro: a PDD reduz o resultado e, por consequência, o capital.

Etapa 3 Síntese — provisão adicional (20 pts)

Prompt: Qual a provisão adicional necessária?

A) R$ 600 mi ✓ Correto
ΔPDD = (NPL_pós − NPL_pré) × cobertura = (1.800 − 800) × 60% = 1.000 × 60% = R$ 600 mi.
B) R$ 1.000 mi ✗
Erro: não aplicou a cobertura (60%). Provisão adicional = 1.000 × 60% = 600.
C) R$ 1.080 mi ✗
Erro: 1.080 é o estoque de provisão pós-recessão; o adicional é 1.080 − 480 = 600.
D) R$ 480 mi ✗
Erro: 480 é a provisão antes da recessão; o adicional é 600.

Reflexão — risco residual (25 pts)

Prompt: Qual o risco residual das alavancas de damage control?

A) Reestruturar pode virar extend-and-pretend se o tomador não recupera; vender NPL realiza a perda barata; e apertar demais a originação aprofunda a própria recessão. ✓ Correto
Cada alavanca tem um custo escondido: adiamento, desconto na venda, ou pró-ciclicidade.
B) Nenhum: reestruturar resolve a inadimplência. ✗
Erro: pode só adiar a perda se o tomador não recupera.
C) Vender NPL recupera o valor de face. ✗
Erro: a venda é com forte desconto — realiza a perda.
D) Apertar a originação não tem efeito colateral. ✗
Erro: aperto excessivo é pró-cíclico e sufoca bons tomadores.

Cenário S8.4 — Carteira Espelho Avançado

S8.4 · Carteira Espelho · Avançado · 24 min

Concentração: a perda que a PE não enxerga

Blurb (card): Duas carteiras, mesma perda esperada, riscos opostos. Por que a concentração torna uma delas muito mais perigosa — e o que fazer a respeito?

Pergunta-chave: por que duas carteiras com a mesma PE podem ter riscos muito diferentes?

Contexto (narrativa)

Você compara duas carteiras de R$ 5.000 mi, ambas com PD média 4% e LGD 50% — logo, a mesma perda esperada. A Carteira Diversificada tem 500 tomadores de R$ 10 mi; a Carteira Concentrada tem 10 tomadores de R$ 500 mi. Sua tarefa: mostrar que a PE é idêntica, entender por que o risco não é, e quantificar o pior caso de um único nome — para então decidir a política de concentração.

Etapa 1 Leitura — perda esperada das carteiras (20 pts)

Prompt: Qual a perda esperada de cada carteira?

A) R$ 100 mi nas duas (idêntica) ✓ Correto
PE = PD × LGD × EAD = 4% × 50% × 5.000 = R$ 100 mi — igual nas duas, pois PD, LGD e tamanho são iguais.
B) Diversificada 100; Concentrada 250 ✗
Erro: confundiu PE com o pior caso. A PE é igual (100); 250 é a perda de um único grande nome na concentrada.
C) R$ 200 mi cada ✗
Erro: esqueceu a LGD. PE = 4% × 50% × 5.000 = 100 (não 4% × 5.000 = 200).
D) Não dá para calcular a PE da concentrada ✗
Erro: a PE calcula-se igual (PD × LGD × EAD) = 100; o que difere é a perda inesperada, não a PE.

Etapa 2 Mecanismo — mesma PE, risco diferente (20 pts)

Prompt: Por que carteiras com a mesma PE têm riscos diferentes?

A) A PE é a média; ignora correlação e granularidade. A concentração eleva a perda inesperada — um único default grande é catastrófico frente à PE. ✓ Correto
A PE mede a média esperada; a dispersão em torno dela (perda inesperada) é muito maior quando poucos nomes concentram a exposição.
B) Não há diferença: PE igual = risco igual. ✗
Erro: a PE é a média; a perda inesperada (dispersão) é muito maior na concentrada.
C) A concentrada é menos arriscada (menos nomes para monitorar). ✗
Erro: menos nomes significa mais risco de concentração — cada default pesa muito mais.
D) A diferença é só a LGD. ✗
Erro: a LGD é igual (50%); a diferença é a granularidade/concentração das exposições.

Etapa 3 Síntese — pior caso de um nome (20 pts)

Prompt: Qual a perda se o maior tomador de cada carteira der default?

A) Concentrada R$ 250 mi (2,5× a PE); Diversificada R$ 5 mi (5% da PE) ✓ Correto
Concentrada: 500 × 50% = R$ 250 mi = 2,5× a PE total (100). Diversificada: 10 × 50% = R$ 5 mi = 5% da PE.
B) Concentrada R$ 500 mi ✗
Erro: esqueceu a LGD. Perda = exposição × LGD = 500 × 50% = 250.
C) Concentrada R$ 100 mi (= a PE) ✗
Erro: o pior caso de um nome (250) excede a PE total (100) em 2,5×.
D) Diversificada R$ 250 mi ✗
Erro: usou a exposição da concentrada. Na diversificada o maior nome é R$ 10 mi → perda 5 mi.

Encruzilhada (decisão · 0 pts)

Prompt: Que política adotar para a Carteira Concentrada?

Caminho A — Aceitar a concentração pela margem
Relação e receita altasCauda perigosa

Trade-off: grandes clientes trazem margem e relacionamento, mas um único default ameaça o resultado do ano.

Caminho B — Impor limites e diversificar
Corta a perda inesperadaGranularidade maiorPode expulsar bons negócios

Trade-off: limites de single-name e setoriais reduzem a cauda, mas podem afastar relações rentáveis.

Caminho C — Transferir a concentração (seguro/sindicalização/securitização)
Mantém o clienteReduz a caudaCusto do hedge

Trade-off: divide ou segura a exposição sem perder a relação, ao custo do prêmio/deságio da transferência.

Reflexão — risco residual (25 pts)

Prompt: Qual o limite da diversificação?

A) Diversificar elimina o risco idiossincrático, não o sistêmico — uma recessão ampla atinge todos juntos (volta ao S8.3); e limites rígidos podem tirar o banco de bons negócios. ✓ Correto
Granularidade protege de um default isolado, mas não de um choque correlacionado que eleva a PD de toda a carteira.
B) Nenhum: diversificar elimina todo o risco. ✗
Erro: elimina o idiossincrático, não o sistêmico (recessão ampla).
C) Concentração não tem relação com recessão. ✗
Erro: na recessão (risco sistêmico) até a diversificada sofre; a concentração agrava.
D) Limites de concentração não têm custo. ✗
Erro: podem expulsar relações rentáveis (custo de oportunidade).
