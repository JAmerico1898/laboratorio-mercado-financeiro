Novo módulo do Laboratório de Tesouraria de Empresas: quatro cenários interativos sobre regulação de capital bancário, no mesmo padrão pedagógico do cenário-referência “Indústria Alfa”. O aluno escolhe opções, o app valida e mostra a memória de cálculo; tudo que resolve cada etapa está em KeyFacts; o volumoso (BP/DRE) fica em demonstrações ocultáveis.

1. Visão geral do módulo

O módulo Regulação Bancária isola, em quatro casos, os principais motores do Índice de Basileia (IB = PR / RWA). Cada cenário foca um único eixo; juntos cobrem o tema com progressão de dificuldade.

2. Arcabouço de capital — regra única

Para fins didáticos, o módulo adota um requisito de capital único e igual para todos os bancos, sem decompor em Capital Principal / Nível I / ACP e sem Razão de Alavancagem:

Requisito Índice de Basileia  IB = PR / RWA ≥ 10,5%
  • PR = Patrimônio de Referência (capital regulatório); no módulo, simplificado como ≈ Patrimônio Líquido do banco.
  • RWA = ativos ponderados pelo risco = Σ (exposição × FPR).
  • FPR = fator de ponderação de risco por classe de ativo.
  • Banco com IB ≥ 10,5% está compliant; abaixo disso, em descumprimento (sujeito a plano de regularização / restrição a dividendos).

Exibição da regra (decisão de produto): a regra aparece nos dois lugares —

  1. Chip global fixo (GlobalRuleChip): faixa navy sempre visível no topo de cada cenário, idêntica ao chip acima (“Requisito · IB = PR/RWA ≥ 10,5%”).
  2. KeyFact destacado em cada cenário: um tile “REQUISITO DE CAPITAL · IB ≥ 10,5%” entre os KeyFacts, para autossuficiência da etapa.
Rigor normativo: 10,5% e os FPR usados são uma simplificação ilustrativa de Basileia III / Resoluções CMN-BCB, calibrada para ensino. Não tratar como dispositivo normativo vigente; se o curso exigir aderência exata, marcar “verificar” e conferir os percentuais atuais antes de publicar.

4. Máquina de estados (jornada do cenário)

card → contexto → etapas (3, sequenciais) → encruzilhada → resultado(caminho) → reflexão → conclusão
  1. contexto — narrativa com termos destacados + KeyFacts + demonstrações ocultáveis.
  2. etapas — 3 múltiplas escolhas com revelação progressiva: a Etapa N+1 só abre após acerto da Etapa N. Cada opção exibe memória de cálculo (verde se certa, vermelha se errada). Erro não pontua e permite nova tentativa. Pontua na 1ª seleção correta.
  3. encruzilhada — 3 cards de decisão (A/B/C); não há “certo”. Escolher leva ao resultado correspondente. 0 pontos.
  4. resultado(caminho) — headline + caption + tiles de variação (deltas) + explicação do trade-off.
  5. reflexão — 1 MC sobre o risco residual / o que o caminho NÃO resolveu (25 pts).
  6. conclusão — “PONTUAÇÃO FINAL X / 85” + “Tentar outro cenário” / “Finalizar e voltar”.

Navegação permitida: “← Etapa anterior” e troca de caminho na encruzilhada. A barra de progresso reflete as 3 etapas (como na referência); a transição 0/85 → 60/85 (fim das etapas) → 85/85 (após reflexão) deve bater.

6. Modelo de dados (TypeScript)

Esqueleto tipado; scenarios-s6.ts exporta Scenario[]. Strings de conteúdo aceitam HTML inline restrito (<strong>, <em>, <br>) e devem ser sanitizadas na renderização.

interface KeyFact { label: string; value: string; tone?: "default" | "positive" | "warning"; }

interface Statement {
  id: string; title: string; columns: string[];
  rows: { label: string; values: string[]; emphasis?: boolean }[];
  note?: string;
}

interface Option {
  id: string; text: string; correct: boolean;
  feedback: string;            // memória de cálculo (acerto OU erro), SEMPRE com a conta
}

interface Etapa {
  id: string; label: string; prompt: string;
  options: Option[];           // 4 opções, 1 correta
  points: number;              // 20
}

interface DeltaMetric { label: string; value: string; tone: "positive" | "negative" | "neutral" | "risk"; }

interface Resultado { headline: string; caption: string; metrics: DeltaMetric[]; explanation: string; }

interface Branch { id: "A" | "B" | "C"; title: string; summary: string; resultado: Resultado; }

interface Reflexao { prompt: string; options: Option[]; points: number; } // 25

interface Scenario {
  id: string;                  // "s6-1"
  code: string;                // "S6.1"
  order: number;
  title: string;
  bank: string;                // "Banco Crescente S.A."
  difficulty: "intermediario" | "avancado";
  estMinutes: number;
  blurb: string;               // texto do card na grade
  archetype: string;           // eixo isolado
  context: string;             // narrativa do CONTEXTO
  keyFacts: KeyFact[];         // inclui o tile "REQUISITO · IB ≥ 10,5%"
  statements: Statement[];     // BP, DRE e (S6.3/S6.4) tabela de FPR/buckets
  etapas: Etapa[];             // 3
  encruzilhada: { prompt: string; branches: Branch[] };
  reflexao: Reflexao;
  maxScore: number;            // 85
}

// Constante global reutilizada pelo GlobalRuleChip e por um KeyFact:
export const CAPITAL_RULE = { label: "Requisito de capital", value: "IB = PR/RWA ≥ 10,5%" };

7. Pontuação e persistência

  • 3 etapas × 20 + reflexão 25 = 85. Encruzilhada = decisão (0 pts).
  • Pontua na 1ª seleção correta de cada etapa/reflexão; tentativas erradas anteriores não descontam, mas não readicionam pontos.
  • Estado por cenário: { phase, currentEtapaIndex, answers, chosenBranch, score, completed }.
  • Persistir em localStorage por cenário (chave por scenarioId). Permitir “← Etapa anterior” e troca de caminho na encruzilhada.
  • O progresso do módulo (x/4 concluídos) deriva de completed de cada cenário.

9. Convenções de conteúdo

  • Autossuficiência: tudo que resolve as etapas está nos KeyFacts; o volumoso (BP/DRE, tabelas de FPR/buckets) vai nas demonstrações ocultáveis.
  • Memória de cálculo SEMPRE com a conta (fórmula + números). No acerto, reforça o conceito; no erro, aponta o equívoco específico. Cada opção incorreta tem sua “memória de erro”.
  • FPR — abordagem mista: S6.1 e S6.2 usam o RWA/FPR médio diretamente (sem tabela por classe); S6.3 e S6.4 expõem tabela de FPR por classe e exigem que o aluno compute RWA = Σ exposição × FPR.
  • Destaques: <strong> para números-chave; <em>/teal para conceitos.
  • Números internamente consistentes e implementáveis literalmente (valores em R$ milhões).

10. Checklist de QA

  • Os KeyFacts bastam para resolver todas as etapas? O resto está ocultável?
  • Cada etapa tem 4 opções plausíveis, 1 correta e memória com a conta (inclusive nas erradas)?
  • Os 3 caminhos da encruzilhada levam a resultados realmente diferentes (deltas e trade-offs distintos)?
  • A pontuação soma 85 (3×20 + 25)? A transição 0 → 60 → 85 confere?
  • Todos os bancos partem com IB ≥ 10,5% (compliant) — o choque/decisão é que derruba o índice?
  • Chip global presente e KeyFact da regra em todos os cenários?
  • Há progressão de dificuldade (S6.1/S6.2 intermediário → S6.3/S6.4 avançado)?

Este cenário é o template canônico: vem com as 4 opções por etapa e a memória de erro de cada incorreta. Os demais cenários (S6.2–S6.4) seguem a mesma estrutura.

S6.1 · Banco Crescente S.A. · Intermediário · 20 min

Crescimento orgânico corrói o colchão de capital

Blurb (card): O Banco Crescente vem expandindo a carteira de crédito a 25% ao ano. Apesar de lucrativo, o CFO teme que o ritmo esteja consumindo o Índice de Basileia. Sua tarefa: medir o IB atual, entender o que o derruba e projetar onde ele termina o ano.

Etapa 1 Leitura — IB atual (20 pts)

Prompt: Qual é o Índice de Basileia atual do Banco Crescente?

A) 12,0% ✓ Correto
IB = PR / RWA = 1.200 / 10.000 = 12,0%. Acima do requisito de 10,5% → o banco parte saudável, com colchão de 1,5 p.p.
B) 8,0% ✗
Erro: usou o caixa (800) no numerador. O capital regulatório é o PR (≈ PL = 1.200), não o caixa. IB = 1.200/10.000 = 12,0%.
C) 10,5% ✗
Erro: 10,5% é o requisito, não o índice do banco. Calcule PR/RWA = 1.200/10.000 = 12,0%.
D) 15,0% ✗
Erro: o denominador é o RWA (10.000), não os TVM (3.000) nem a carteira. IB = 1.200/10.000 = 12,0%.

Etapa 2 Mecanismo — o que derruba o IB (20 pts)

Prompt: Executando o plano de crescer +25% o RWA financiado só com lucro retido, o que acontece com o IB?

A) O RWA cresce 25% enquanto o capital cresce só 7,5% — o IB cai porque o denominador cresce mais que o numerador. ✓ Correto
ΔRWA = +25%. Capital gerado internamente = lucro retido / PR = 90/1.200 = 7,5%. Como 25% > 7,5%, o numerador não acompanha o denominador → IB cai.
B) O IB sobe: mais carteira gera mais lucro e mais capital. ✗
Erro: o lucro retido (90) é muito menor que o aumento do RWA (+2.500). O capital não acompanha; o IB cai.
C) O IB fica estável: o lucro retido cobre o crescimento. ✗
Erro: 90 de capital novo contra 2.500 de RWA novo — não cobre. O IB cai.
D) Depende só do payout; com 40% de retenção o índice se mantém. ✗
Erro: o payout é 40%, logo retém-se 60% (R$ 90). Mesmo assim 90 ≪ 2.500 de RWA novo; o payout não muda a aritmética a favor.

Etapa 3 Síntese — IB projetado (20 pts)

Prompt: Qual o IB projetado ao fim do ano se o plano de crescimento for executado como está?

A) 10,3% — abaixo de 10,5% (descumprimento). ✓ Correto
PR projetado = 1.200 + 90 = 1.290. RWA projetado = 10.000 × 1,25 = 12.500. IB = 1.290/12.500 = 10,3% → abaixo do requisito de 10,5%: o banco entra em descumprimento.
B) 12,0% — inalterado. ✗
Erro: não atualizou o RWA. Com RWA 12.500 e PR 1.290, o IB cai para 10,3%.
C) 9,3% ✗
Erro: cresceu o RWA mas esqueceu o lucro retido no PR. PR = 1.290 (não 1.200). IB = 1.290/12.500 = 10,3%.
D) 10,1% ✗
Erro: reteve 40% do lucro (R$ 60) em vez de 60%. Payout de 40% ⇒ retenção de 60% (R$ 90). PR = 1.290; IB = 10,3%.

Encruzilhada (decisão · 0 pts)

Prompt: O conselho precisa definir a estratégia diante da projeção de descumprimento. Qual caminho seguir?

Caminho A — Manter o ritmo de +25% ao ano

Resultado · headline: “Crescimento máximo, capital furado”

IB ano 1: 10,3%ano 2: ~9,0%ano 3: ~7,9% Carteira +95% em 3 anosDescumprimento recorrente

Trade-off: maximiza crescimento de curto prazo, mas o IB despenca a cada ciclo — descumprimento estrutural, plano de regularização e provável restrição a dividendos.

Caminho B — Calibrar o crescimento à geração de capital

Resultado · headline: “Disciplina de capital, crescimento modesto”. Ex.: crescer só +20% → IB = 1.290/12.000 = 10,8%.

IB ~10,8% (folga)Carteira +20% (em vez de +25%)Market share cede

Trade-off: preserva o IB acima de 10,5%, mas cresce abaixo do potencial e perde margem/participação.

Caminho C — Captar capital para sustentar +25%/ano

Resultado · headline: “Crescimento sustentado, acionista diluído”.

IB mantido ~10,5–11%Capital novo ~R$ 200–300 M/anoDiluição recorrente

Trade-off: sustenta crescimento e IB, mas exige captações sucessivas (diluição/custo de capital a cada rodada).

Reflexão — risco residual (25 pts)

Prompt: Mesmo que o banco capte capital agora (caminho C), qual risco residual permanece?

A) Enquanto a geração interna de capital (7,5%) ficar abaixo do crescimento do RWA (25%), o banco precisará captar repetidamente — é estrutural, não pontual. ✓ Correto
O crescimento sustentável de ativos sem perder capital ≈ ROE × retenção. Enquanto o crescimento do RWA superar a geração de capital, o IB tende a cair a cada ciclo — a captação resolve um ano, não o descasamento.
B) Nenhum: uma vez capitalizado, o IB fica permanentemente resolvido. ✗
Erro: a captação cobre um exercício; o descasamento entre crescimento e geração de capital recorre.
C) O único risco é o custo da dívida subir. ✗
Erro: o risco central é de capital regulatório, não de custo de funding isolado.
D) O risco é o payout cair. ✗
Erro: reduzir payout ajuda, mas mesmo com retenção total (150) < 2.500 de RWA novo — não resolve o descasamento.

Perda na carteira: desalavancar ou capitalizar

Etapa 1 Leitura — IB pós-perda (20 pts)

Prompt: Após reconhecer R$ 600 M de PDD adicional, qual o IB do Banco Atlântico?

A) 9,0% ✓ Correto
A PDD reduz o resultado e, por consequência, o capital: PR = 2.400 − 600 = 1.800. IB = 1.800/20.000 = 9,0% → abaixo de 10,5%.
B) 12,0% ✗
Erro: não deduziu a perda. A PDD adicional reduz o capital; PR cai para 1.800, IB = 9,0%.
C) 7,0% ✗
Erro: deduziu a perda também do RWA. A perda atinge o capital, não o RWA; PR 1.800 / RWA 20.000 = 9,0%.
D) 11,0% ✗
Erro: deduziu só metade da PDD. Toda a PDD de 600 reduz o capital; PR 1.800; IB = 9,0%.

Etapa 2 Mecanismo — componente atingido (20 pts)

Prompt: A perda de crédito derruba o IB atingindo qual componente?

A) O numerador (capital/PR), via resultado; o RWA fica estável porque as exposições foram provisionadas, não baixadas. ✓ Correto
PDD é despesa → reduz lucro → reduz PL/PR (numerador). Exposições provisionadas continuam no balanço → RWA estável.
B) O denominador (RWA), porque a carteira encolhe. ✗
Erro: provisionar não baixa a exposição; o RWA permanece em 20.000. O atingido é o capital.
C) Ambos igualmente. ✗
Erro: o efeito imediato é no capital; o RWA só cairia com baixa (write-off) ou venda da exposição.
D) Nenhum: PDD é conta de resultado e não afeta o capital. ✗
Erro: o resultado compõe o capital (via lucros/prejuízos acumulados); a PDD o reduz.

Etapa 3 Síntese — alavancas de recomposição (20 pts)

Prompt: Para voltar a cumprir 10,5%, quanto o banco precisa em CADA alavanca isolada?

A) Capital: injetar R$ 300 M; OU desalavancar: reduzir o RWA em ≈ R$ 2.857 M. ✓ Correto
Capital → PR ≥ 0,105 × 20.000 = 2.100; déficit = 2.100 − 1.800 = R$ 300 M. Desalavancagem → RWA ≤ 1.800/0,105 = 17.143; corte = 20.000 − 17.143 ≈ R$ 2.857 M.
B) Capital: R$ 600 M; desalavancar: R$ 600 M. ✗
Erro: R$ 600 era a perda. O déficit para 10,5% é R$ 300 M (capital) ou ≈ R$ 2.857 M (RWA).
C) Capital: R$ 300 M; desalavancar: R$ 300 M. ✗
Erro: o corte de RWA não é igual ao aporte. RWA ≤ 1.800/0,105 → corte ≈ R$ 2.857 M.
D) Capital: R$ 2.100 M; desalavancar: R$ 17.143 M. ✗
Erro: confundiu o nível-alvo (PR 2.100; RWA 17.143) com o ajuste necessário (déficit 300; corte 2.857).

A) Se a causa (concentração setorial) persistir, recompor capital não evita um 2º choque; e desalavancar vendendo os ativos líquidos de baixo risco piora a densidade de RWA do que sobra. ✓ Correto
A recomposição corrige o índice, não a origem da perda. Vender o que é líquido e de baixo risco deixa a carteira mais arriscada na média (densidade de RWA maior).

Erro: a fonte da perda (concentração) segue ativa.
C) O risco é só de liquidez. ✗
Erro: o risco central é a recorrência da perda de crédito por concentração.

Etapa 2 Mecanismo — por que B consome mais capital (20 pts)

D) B não consome mais capital; consome igual. ✗
Erro: RWA_B 9.000 vs RWA_A 5.000 → exigências diferentes (945 vs 525).

B) B, porque tem maior margem (350 > 200). ✗

D) A, com 4,0%. ✗
Erro: usou a exposição (5.000) no denominador. O denominador é o capital exigido (10,5%×RWA = 525). RAROC_A = 38,1%.

Cenário S6.4 — Banco Horizonte Avançado

D) Recompor RWA também recompõe o capital. ✗
