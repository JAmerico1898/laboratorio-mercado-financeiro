1. Visão geral e objetivos pedagógicos

O módulo ensina, por meio de casos aplicados, como empresas e bancos usam FIDCs (Fundos de Investimento em Direitos Creditórios) para financiar carteiras de recebíveis, e como o desenho do fundo (cedente, sacado, subordinação, indexadores) determina onde o risco se aloca. Cada cenário reproduz a mesma jornada do módulo existente: contexto rico → etapas de diagnóstico → encruzilhada de decisão com resultados divergentes → reflexão → conclusão pontuada.

Ao final, o aluno deve saber: (i) o ciclo de caixa da originação até a cessão; (ii) o efeito da subordinação no caixa, no giro de capital e no desreconhecimento; (iii) como os eixos cedente e sacado (mono/multi) deslocam o risco; e (iv) como descasamentos de indexador (PRÉ × CDI) são resolvidos dentro do fundo.

2. Stack e integração ao app existente

  • Framework: Next.js (App Router) + React + TypeScript, igual ao app atual.
  • Estilo: reutilizar a solução de estilo já usada (Tailwind e/ou CSS Modules) e os componentes compartilhados (botões, cards, badges, accordion). Não introduzir nova biblioteca de UI.
  • Integração: o módulo é um “capítulo” a mais. Deve aparecer no índice/menu de módulos do laboratório como os demais e respeitar o mesmo layout de página (cabeçalho, breadcrumb, contador de pontuação).
  • Conteúdo data-driven: toda a renderização parte de um arquivo de dados tipado (scenarios.ts). Nenhum texto de cenário deve ficar hard-coded em componentes — os componentes são genéricos e recebem os dados por props.
  • Sem dependências de rede: os datasets são estáticos no bundle. Nenhuma chamada externa.

4. Fluxo do usuário (máquina de estados)

O player de cada cenário é uma máquina de estados com revelação progressiva (uma fase de cada vez, conteúdo anterior permanece visível e rolável, como nos prints):

context  →  etapas (etapa 1 … N, sequenciais)  →  encruzilhada  →  resultado(branch)  →  reflexao  →  conclusao

Regras de transição

  1. context: mostra narrativa + KeyFacts + demonstrações ocultáveis. Botão não é necessário; a Etapa 1 já aparece abaixo (como na “Image 2 → 3”).
  2. etapas: a Etapa n+1 só é revelada após a Etapa n ser respondida corretamente. Selecionar qualquer opção mostra a memória de cálculo daquela opção (verde se correta, vermelha se incorreta). Opção incorreta não avança nem pontua; permite nova tentativa. Opção correta fixa a pontuação da etapa e revela a próxima.
  3. encruzilhada: revelada após a última etapa correta. Mostra 3 cards de decisão (A/B/C). Escolher um card é uma decisão (não há resposta “certa”), leva ao resultado daquele caminho.
  4. resultado: página com headline + tiles de variação (deltas) + explicação detalhada do caminho escolhido. Botão “Continuar para reflexão”.
  5. reflexao: 1 questão de múltipla escolha que testa o entendimento do trade-off do caminho escolhido. Pontua.
  6. conclusao: feedback final + “PONTUAÇÃO FINAL X / 85” + botões “Tentar outro cenário” e “Finalizar e voltar”.
O usuário pode voltar uma etapa (botão “← Etapa anterior”, ver “Image 7/8”) e pode trocar de caminho na encruzilhada antes de concluir (refaz o resultado). A barra de etapas no topo (3–4 segmentos) preenche em rust conforme avança.

6. Modelo de dados (tipos TypeScript)

Arquivo data/fidc/scenarios.ts exportando const scenarios: Scenario[]. Strings de conteúdo aceitam HTML inline restrito (apenas <strong>, <em>, <br>) renderizado de forma segura (sanitizado).

type Difficulty = "intermediario" | "avancado";
type Tone = "default" | "positive" | "warning";
type DeltaTone = "positive" | "negative" | "neutral" | "risk";

interface KeyFact { label: string; value: string; tone?: Tone; }

interface StatementRow { label: string; values: string[]; emphasis?: boolean; }
interface Statement {
  id: string;
  title: string;            // "Balanço Patrimonial", "DRE", "Regulamento do FIDC", "Carteira", ...
  columns: string[];        // cabeçalho da tabela
  rows: StatementRow[];
  note?: string;            // nota de rodapé opcional
}

interface Option {
  id: string;
  text: string;             // enunciado da opção
  correct: boolean;
  feedback: string;         // MEMÓRIA DE CÁLCULO (HTML inline restrito); explica por que certo/errado
}

interface Etapa {
  id: string;               // "etapa-1"
  label: string;            // "Etapa 1 — Liquidez e prazos médios"
  prompt: string;           // enunciado da questão
  options: Option[];        // 4 opções; exatamente 1 com correct:true
  points: number;           // padrão 20
}

interface DeltaMetric { label: string; value: string; tone: DeltaTone; }

interface Resultado {
  headline: string;         // "Subordinação a 20% manteve o giro, mas..."
  caption: string;          // "Caminho B: ..."
  metrics: DeltaMetric[];   // tiles de variação
  explanation: string;      // memória detalhada do caminho (HTML inline restrito)
}

interface Branch {
  id: "A" | "B" | "C";
  title: string;            // "Cenário A — ..."
  summary: string;          // descrição do card (HTML inline restrito)
  resultado: Resultado;
}

interface Reflexao {
  prompt: string;
  options: Option[];        // 4 opções; 1 correta
  points: number;           // padrão 25
}

interface Scenario {
  id: string;               // "s5-1"
  code: string;             // "S5.1"
  order: number;
  title: string;
  difficulty: Difficulty;
  estMinutes: number;
  blurb: string;            // texto do card na grade
  archetype: string;        // "mono cedente / multi sacado"
  context: string;          // narrativa do box CONTEXTO (HTML inline restrito)
  keyFacts: KeyFact[];
  statements: Statement[];  // ocultáveis (accordion)
  etapas: Etapa[];          // 3 etapas
  encruzilhada: { prompt: string; branches: Branch[] };  // 3 branches
  reflexao: Reflexao;
  maxScore: number;         // 85
}

7. Pontuação, estado e persistência

  • Distribuição: 3 etapas × 20 = 60 + reflexão 25 = 85. A encruzilhada é decisão (0 pontos). Confere com os prints (0/85 no início, 60/85 no resultado, 85/85 na conclusão).
  • Regra: pontua na primeira seleção correta de cada etapa/reflexão. Seleção incorreta mostra a memória de cálculo do erro, não pontua e permite nova tentativa (sem penalidade por padrão; deixar penalidade configurável por flag).
  • Estado do player (React): { phase, currentEtapaIndex, answers: Record<etapaId, optionId>, chosenBranch, score, completed }.
  • Persistência: localStorage por scenarioId para retomar (chave fidc:progress:<id>) e marcar concluído na grade. Integrar ao store de progresso do app se existir.
  • Reset: “Tentar outro cenário” reinicia o estado do cenário atual ao reentrar.

9. Convenções de conteúdo e acessibilidade

  • Destaques no contexto: usar <strong> para números-chave e <em>/teal para conceitos. Padrão visual igual à “Image 2”.
  • Memória de cálculo: sempre mostrar a fórmula e a conta, não só o conceito (ver exemplos da seção 10). Em acerto, reforçar o conceito; em erro, apontar o equívoco específico.
  • KeyFacts = autossuficiência: tudo que é necessário para resolver as etapas deve estar nos KeyFacts em destaque; o que é volumoso (BP, DRE, regulamento, carteira) vai nas demonstrações ocultáveis.
  • Acessibilidade: opções como button/radio com aria; foco visível; contraste AA; accordion com aria-expanded; navegação por teclado; prefers-reduced-motion respeitado nas transições.
  • Responsivo: grade de cards 2-col → 1-col; KeyFacts 4→2→1; tabelas com scroll horizontal no mobile.

S5.1 — Credenciadora PagSeg: antecipação, cessão e a economia da subordinação

Contexto

Você é analista de tesouraria da PagSeg Adquirência S.A., credenciadora de cartões. A empresa antecipa recebíveis aos lojistas e financia essa operação cedendo os recebíveis a um FIDC mono cedente / multi sacado. O CFO quer entender quanto caixa a estrutura realmente devolve e qual o efeito da subordinação retida.

Etapa 1 — Caixa novo na cessão (20 pts)

Com subordinação de 20% e preço de cessão de R$ 96,50, quanto de caixa novo (de terceiros) a PagSeg recupera por recebível cedido?

R$ 96,50 — o preço integral de cessão
R$ 77,20 — apenas a fatia sênior ✓
R$ 19,30 — apenas a subordinada
R$ 95,50 — o valor pago ao lojista
Correto. Dos R$ 96,50, só a cota sênior (80% × 96,50 = R$ 77,20) é caixa de terceiros. Os 20% (R$ 19,30) a PagSeg integraliza como cota subordinada retida — é dinheiro dela voltando ao fundo. Caixa novo recuperado ≈ R$ 77,20, não os R$ 96,50 cheios.

Memórias de erro: 96,50 — ignora que 20% é capital próprio retido; 19,30 — confunde a parte retida com o caixa recebido; 95,50 — é o desembolso da antecipação, não o caixa da cessão.

Etapa 2 — Capital efetivamente comprometido (20 pts)

A PagSeg pagou R$ 95,50 ao lojista e recuperou R$ 77,20 de caixa sênior. Qual o capital líquido que permanece comprometido na operação?

R$ 19,30 — exatamente a subordinada
R$ 18,30 — caixa líquido comprometido (95,50 − 77,20) ✓
R$ 1,00 — apenas a margem
R$ 0 — o capital girou integralmente
Correto. Fluxo da operação: −95,50 (lojista) +77,20 (sênior) = −R$ 18,30 de caixa comprometido, mais a cota subordinada de R$ 19,30 que ela carrega. A diferença (19,30 − 18,30 = R$ 1,00) é exatamente a margem de cessão já realizada (96,50 − 95,50). O capital preso por operação ≈ o tamanho da subordinação.

Etapa 3 — Os dois “R$ 1,00” (20 pts)

A margem de cessão (96,50 − 95,50 = R$ 1,00) é repartida com a cota sênior?

Sim — o sênior recebe parte dessa margem como remuneração
Não — essa margem é 100% da PagSeg; o sênior é pago pelo carrego (97,50 − 96,50), não por ela ✓
Sim — é dela que sai todo o rendimento do fundo
Não — porque o sênior não tem remuneração
Correto. São dois R$ 1,00 distintos que coincidem nos números: (A) margem de cessão = preço − custo = 96,50 − 95,50, realizada no t0, 100% da cedente; (B) carrego do fundo = face − preço = 97,50 − 96,50, ganho do t0 ao D+30, que é repartido — sênior (yield) primeiro, subordinada (residual) depois. O sênior é pago a partir de (B), nunca de (A). O deságio bruto total (97,50 − 95,50 = R$ 2,00) divide-se em: margem A (1,00, PagSeg) + yield sênior (X, de B) + residual subordinada (1,00 − X, PagSeg).

Encruzilhada — Defina o nível de subordinação

Cada nível equilibra giro de capital, custo do sênior e tratamento contábil de forma diferente.

A — Subordinação 10%
Reter menos: cada R$ 1 de capital sustenta R$ 10 de carteira (alavancagem 10×). Mais giro, mais volume.
B — Subordinação 20%
Equilíbrio: alavancagem 5×; colchão confortável para o sênior.
C — Subordinação 35%
Reter mais: sênior muito seguro e barato, porém alavancagem ~2,9× e risco contábil.

Resultados (por caminho)

Caminho A (10%): headline “Giro máximo, sênior mais caro e colchão fino”. Tiles — Alavancagem: 10× (positivo); Caixa recuperado/un.: R$ 86,85 (90%×96,50, positivo); Custo do sênior: ↑ maior (risco); Desreconhecimento: provável OK (neutro). Explicação: mais volume, mas o sênior exige prêmio por colchão menor; sensível a um pico de perdas.

Caminho B (20%): headline “Equilíbrio entre giro e proteção”. Tiles — Alavancagem: 5×; Caixa recuperado/un.: R$ 77,20; Custo do sênior: médio; Desreconhecimento: OK. Explicação: padrão de mercado para recebível de cartão pulverizado.

Caminho C (35%): headline “Sênior barato, mas capital travado e risco contábil”. Tiles — Alavancagem: 2,9× (negativo); Caixa recuperado/un.: R$ 62,73 (negativo); Custo do sênior: baixo (positivo); Desreconhecimento: em risco (risk). Explicação: reter risco demais pode impedir a transferência substancial e manter o ativo no balanço.

Reflexão (25 pts)

Qual o maior risco de reter subordinação alta demais (caminho C)?

Impedir o desreconhecimento contábil — o ativo permanece no balanço e o alívio de capital desaparece ✓
O sênior fica caro demais
O lojista deixa de antecipar
Nenhum — quanto mais subordinação, sempre melhor
Correto. Subordinação muito alta significa reter substancialmente os riscos e benefícios — o que pode descaracterizar a venda definitiva (true sale), obrigando a manter o recebível no balanço. Some o alívio de capital que motivou a estrutura, além de travar mais caixa (menor giro). Existe um ponto ótimo: subordinação suficiente para baratear o sênior, baixa o bastante para desreconhecer.

Intermediário · S5.2 · ~22 min · multi cedente / mono sacado

S5.2 — Risco sacado: FIDC Fornecedores VarejoMax

Contexto

A VarejoMax S.A. é uma grande varejista (o sacado-âncora). Cerca de 120 fornecedores cedem a um FIDC os recebíveis que têm a receber da VarejoMax — um arranjo de reverse factoring. Você analisa onde está, de fato, o risco do fundo.

Demonstrações ocultáveis

Statement 1 — “Regulamento (limites e gatilhos)”: limite por cedente 5%; sem limite por sacado (mono); gatilho de amortização antecipada se o rating do sacado cair abaixo de A−.
Statement 2 — “Carteira por cedente”: tabela com os maiores fornecedores e seus % (todos abaixo de 5%).
Statement 3 — “Perfil de crédito da VarejoMax”: alavancagem, cobertura de juros, liquidez e rating — o verdadeiro lastro do fundo.

Etapa 1 — Onde está o risco de crédito? (20 pts)

Com 120 cedentes e um único sacado, onde se concentra o risco de crédito da carteira?

Concentrado no sacado único (VarejoMax) — diversificar cedentes não dilui crédito ✓
Diluído entre os 120 cedentes
Nos fornecedores, pois são quem origina
É risco de mercado, não de crédito
Correto. Os recebíveis são todos devidos pela VarejoMax. Multiplicar cedentes dispersa a originação, mas o devedor final é o mesmo nome — a carteira vale o que vale o crédito do sacado-âncora. Não há diluição de crédito.

Etapa 2 — Efeito da confirmação (reverse factoring) (20 pts)

O que muda quando a VarejoMax confirma formalmente as dívidas cedidas?

Converte o recebível em quase-crédito direto do sacado, removendo risco comercial/disputa do fornecedor ✓
Elimina completamente o risco de crédito
Transfere o risco de volta ao fornecedor
Não muda nada — confirmação é formalidade
Correto. Com a confirmação, some o risco de o fornecedor não ter entregue/haver disputa comercial — o crédito passa a ser, em essência, uma obrigação direta da VarejoMax. O risco do fundo converge para o balanço do sacado, não para a relação fornecedor-âncora.

Etapa 3 — A subordinação protege contra o default do sacado? (20 pts)

Os 8% de subordinação protegem o sênior contra a quebra da VarejoMax?

Sim — absorve integralmente o default do sacado
Não contra o evento de crédito do sacado (sistêmico à carteira); só absorve atrasos/perdas parciais e risco dos cedentes ✓
Sim, em até 8% do default
Sim, porque o rating é AA−
Correto. Se a VarejoMax dá default, a perda atinge toda a carteira de uma vez — os 8% somem rapidamente. A subordinação cobre perdas parciais, atrasos e risco dos cedentes; contra o evento de um único devedor, o que importa é o rating do sacado, não a espessura do colchão.

Encruzilhada — Como tratar o risco do sacado-âncora?

A — Aumentar subordinação para 15%
Mais colchão; custa retorno do sênior; não ataca o risco mono-nome.
B — Exigir confirmação + limite/cedente + gatilho de rating
Mitiga performance e cria porta de saída se o rating cair.
C — Contratar seguro de crédito sobre o sacado
Transfere o evento de default a um terceiro, com custo.

Resultados (por caminho)

A: headline “Mais colchão, mesmo risco de nome”. Tiles — Subordinação: 8%→15% (neutral); Retorno sênior: ↓ (negative); Proteção vs default do sacado: ~nenhuma (risk); Custo de capital: ↑. Explicação: subordinação absorve perdas parciais, não o evento sistêmico de um único devedor.

B: headline “Mitiga performance e cria porta de saída”. Tiles — Risco de disputa: ↓ (positive); Limite/cedente: 5% (positive); Gatilho de rating: ativo (positive); Risco mono-nome remanescente (risk). Explicação: melhora a qualidade e antecipa amortização se a VarejoMax for rebaixada — mas a exposição final continua sendo ao nome.

C: headline “Transfere o risco mono-nome (com custo)”. Tiles — Risco de crédito transferido (positive); Custo do seguro: ↓ retorno (negative); Risco de contraparte do segurador (risk); Spread líquido: ↓. Explicação: única alavanca que ataca diretamente o default do sacado; o preço corrói o spread.

Reflexão (25 pts)

Qual é o maior risco residual deste fundo?

Rebaixamento/default do sacado-âncora — a diversificação de cedentes não ajuda ✓
Inadimplência simultânea dos 120 fornecedores
Risco regulatório de limite de prazo
Risco cambial
Correto. É uma exposição mono-nome: tudo depende da VarejoMax honrar. Pulverizar cedentes só dispersa originação; o crédito é um só. O acompanhamento central é o rating/saúde do sacado e os gatilhos que dão saída antecipada.

Contexto

Você é o gestor de risco de um FIDC aberto de uma securitizadora que compra duplicatas de ~300 cedentes, cada um com milhares de clientes (sacados). Os dois eixos são diversificados — então onde mora o risco?

Demonstrações ocultáveis

Statement 1 — “Regulamento”: limites por cedente/sacado, gatilhos (eventos de avaliação e de amortização antecipada), coobrigação.
Statement 2 — “Concentração da carteira”: top-10 cedentes e top-20 sacados com %.
Statement 3 — “Histórico de perdas e recompras”: série de inadimplência e recompras por coobrigação.

Etapa 1 — Para onde migra o risco? (20 pts)

Com crédito e originação diluídos, qual passa a ser o risco dominante?

Risco operacional/originação — fraude de lastro (duplicata “fria”), cessão em duplicidade, validação heterogênea ✓
Risco de crédito concentrado
Risco de mercado (taxa de juros)
O risco simplesmente desaparece
Correto. Diluir os dois eixos atenua crédito e originador. O que sobra é integridade do lastro: recebível inexistente, duplicata fria, dupla cessão e qualidade desigual entre 300 cedentes. É risco operacional, não de crédito de devedor real.

Etapa 2 — Qual controle ataca a fraude de lastro? (20 pts)

Que conjunto de controles endereça diretamente o risco dominante?

Registro em registradora + verificação de lastro/custódia qualificada + limites por cedente + coobrigação ✓
Aumentar a subordinação
Diversificar ainda mais a carteira
Contratar um swap de taxa
Correto. Fraude de lastro não se resolve com mais diversificação — recebível inexistente não “dilui”. O remédio é verificar o lastro, registrar (evita dupla cessão), limitar por cedente e ter coobrigação. Subordinação e swap atacam outros riscos.

Etapa 3 — Um cedente no limite comete fraude total (20 pts)

Um cedente no limite máximo (3%) tem todo o seu lastro fraudado. Com subordinação de 12% e perda esperada de 1,8%, o sênior é atingido?

Não — 3% + 1,8% = 4,8% < 12% de subordinação; há folga (e ainda há coobrigação) ✓
Sim — 3% já consome o sênior
Sim — a fraude zera o fundo
Não é possível calcular
Correto. A perda do cedente fraudulento (≤ 3%) somada à perda esperada (1,8%) dá 4,8%, dentro dos 12% de subordinação — o sênior fica protegido. É exatamente para isso que servem o limite por cedente (limita o tamanho de uma fraude) e a coobrigação (recompra).

Encruzilhada — Reforçar qual controle?

A — Apertar limite por cedente (3%→1,5%)
Reduz o tamanho de cada fraude; custa escala/receita.
B — Reforçar verificação de lastro + custódia + registradora
Ataca a causa-raiz (duplicata fria, dupla cessão).
C — Exigir coobrigação reforçada/recompra
Devolve o risco ao cedente — depende da solvência dele.

Resultados (por caminho)

A: headline “Mais diluição, menos escala”. Tiles — Limite/cedente: 1,5% (positive); Perda máx por cedente: ↓ (positive); Receita/escala: ↓ (negative); Fraude de lastro: não resolvida (risk). Explicação: diluir reduz o tamanho de uma fraude, mas não impede que ela ocorra.

B: headline “Ataca a causa-raiz”. Tiles — Risco de lastro: ↓↓ (positive); Cobertura por registradora (positive); Custo operacional: ↑ (negative); Risco residual: solvência do cedente (neutral). Explicação: validação + registro elimina duplicata fria e dupla cessão — o risco dominante do quadrante.

C: headline “Devolve o risco ao cedente”. Tiles — Recompra obrigatória (positive); Depende da solvência do cedente (risk); Risco de crédito do cedente (negative). Explicação: coobrigação só vale o quanto o cedente puder honrar — pode falhar exatamente quando mais se precisa.

Reflexão (25 pts)

Por que diversificação não substitui controle de lastro?

A diversificação dilui o crédito de devedores reais, mas não protege contra recebível inexistente/fraudado — esse risco é operacional ✓
Porque diversificar aumenta o risco
Porque a subordinação já cobre tudo
Porque o CDI protege a carteira
Correto. Pulverizar funciona para perdas de crédito de devedores que existem. Um recebível fraudado não tem contraparte para diluir — ele simplesmente não existe. Por isso o controle é verificação e registro de lastro, não diversificação.

A Geradora Helios (cedente único) vende toda a sua energia a um único off-taker via PPA de 15 anos e cede ao FIDC os recebíveis — todos devidos por esse mesmo off-taker. É o quadrante de concentração máxima.

Statement 3 — “Estrutura do fundo”: cotas, conta reserva, gatilhos.

Etapa 1 — O FIDC equivale a quê? (20 pts)

Em termos de risco, a que se assemelha esse fundo?

A uma exposição de crédito praticamente direta ao off-taker único (≈ uma debênture do off-taker) ✓
A uma carteira diversificada de recebíveis
Ao risco operacional da geradora
A um risco de mercado de energia
Correto. Com um cedente e um sacado, o fundo é, na prática, uma exposição mono-nome ao off-taker. Não há pool a diversificar — o risco do sênior é o risco de crédito daquele único devedor.

Etapa 2 — A subordinação protege contra o default do off-taker? (20 pts)

Os 10% de subordinação protegem o sênior se o off-taker quebrar?

Sim — protege integralmente
Praticamente cosmética contra o evento mono-nome — se o off-taker quebra, a carteira falha de uma vez; só absorve atrasos/perdas parciais ✓
Sim, em até 10% do default
Sim, por causa do prazo de 15 anos
Correto. O default do único devedor é uma perda sistêmica à carteira inteira — estoura os 10% imediatamente. A subordinação só ajuda em atrasos e perdas parciais. Contra o evento mono-nome, o remédio seria diversificação (que não existe aqui).

Etapa 3 — Qual rating precifica o sênior? (20 pts)

Que rating é o relevante para o spread do sênior?

O do off-taker — não há diversificação que melhore; o sênior precifica perto do crédito dele ✓
O da geradora cedente
Uma média ponderada cedente/sacado
O rating do administrador do fundo
Correto. Como toda a carteira depende de um nome, o sênior tende a precificar próximo ao crédito do off-taker. Não há pulverização que “suba” a qualidade — é exposição direta a uma única contraparte.

Encruzilhada — Como mitigar a concentração?

A — Conta reserva + step-in/garantia do off-taker

B — Seguro de crédito sobre o off-taker

B: headline “Transfere o default (com custo)”. Tiles — Evento de crédito coberto (positive); Prêmio do seguro (negative); Risco do segurador (risk). Explicação: única que ataca o evento mono-nome diretamente; preço relevante porque é concentrado.

Reflexão (25 pts)

Por que subordinação ≠ proteção contra risco mono-nome?

A subordinação absorve perdas parciais até um limite; o default do único devedor é uma perda sistêmica que estoura o colchão de uma vez — o remédio seria diversificação ✓
Porque subordinação não existe em mono-sacado
Porque o rating A elimina o risco
Porque o PPA garante 15 anos de pagamento
Correto. Subordinação e diversificação são alavancas distintas: a primeira absorve perdas até um teto; a segunda decide se a perda é idiossincrática (tolerável) ou sistêmica a um nome (fatal). Em mono-sacado, mais subordinação não resolve — falta o que diversificar.

O Banco Direto origina crédito PRÉ-fixado (consignado/CDC) mas tem PR baixo e índice de Basileia apertado. Para crescer, cede a carteira a um FIDC e libera capital. O sênior é remunerado em CDI + taxa. Você avalia o alívio de capital e como o descasamento de indexador é resolvido dentro do fundo.

Etapa 1 — De onde vem o alívio de capital? (20 pts)

Qual parcela da estrutura efetivamente alivia o capital regulatório do banco?

A parcela sênior colocada a investidores (o RWA sai); a subordinada retida é cara em capital e o alívio pleno exige transferência significativa de risco ✓
A carteira inteira, automaticamente
A cota subordinada retida
A redução de impostos sobre o lucro
Correto. O alívio vem de tirar o RWA do balanço — e isso só ocorre na fatia sênior financiada por terceiros. A subordinada retida carrega peso de risco alto (ou dedução) no arcabouço de securitização, e o desreconhecimento pleno depende de transferência substancial de risco (venda definitiva).

Etapa 2 — Como o descasamento PRÉ × CDI é absorvido? (20 pts)

O ativo rende fixo (30%) e o sênior cobra CDI + 4% (flutuante). Quem absorve essa diferença dentro do fundo?

O excess spread / cota subordinada (retida pelo banco), que flutua inversamente ao CDI; dimensionado contra um estresse de CDI ✓
O próprio sênior absorve
O deságio de aquisição elimina o descasamento
O tomador do crédito absorve
Correto. O rendimento fixo é “fatiado” em sênior (flutuante) + custos/perdas + excess spread. Como o ativo é fixo e o sênior flutua, é o excess spread (da subordinada) que sobe e desce para fechar a conta: CDI sobe → sênior leva mais → sobra menos ao banco. A razão de subordinação é calibrada para suportar um CDI de estresse sem tocar o sênior.

Etapa 3 — CDI de breakeven (20 pts)

Com ativo a 30%, custos/perdas de 6% e sênior = CDI + 4%, em que CDI o excess spread zera?

CDI = 12%
CDI = 16%
CDI = 20% ✓
CDI = 26%
Correto. Excess spread = 30 − (CDI + 4) − 6 = 20 − CDI; zera em CDI = 20%. Acima disso, o rendimento PRÉ não cobre mais sênior + custos e a estrutura começa a consumir a subordinação. A 12% (hoje), o colchão é de 8%.

Encruzilhada — Como tratar o risco de base?

A — Swap pré × DI (hedge explícito)
Converte o fluxo fixo em CDI; elimina a base; custo + risco de contraparte/margem.
B — FIDC rotativo reprecificando a taxa de cessão
Repassa o CDI corrente às novas compras; o banco origina a taxas PRÉ mais altas.
C — Aumentar subordinação + gatilhos de amortização
Mais colchão e proteção; mais capital travado e menos alívio.

Resultados (por caminho)

A: headline “Elimina o risco de base (com custo)”. Tiles — Risco de base: ↓↓ (positive); Excess spread estabilizado (positive); Custo do swap (negative); Risco de contraparte/margem (risk). Explicação: converte o fluxo fixo em CDI, casando com o sênior; precisa estar previsto no regulamento.

B: headline “Reprecifica para frente”. Tiles — Spread futuro protegido (positive); Sem custo de hedge (positive); Estoque atual ainda exposto (risk); Originação a taxas ↑ (neutral). Explicação: a cada compra o fundo exige rendimento PRÉ maior conforme o CDI sobe; o banco precisa originar mais caro para continuar cedendo.

C: headline “Mais proteção, menos alívio”. Tiles — Subordinação: ↑ (positive); Gatilhos protegem o sênior (positive); Capital travado: ↑ (negative); Alívio de RWA: ↓ (negative). Explicação: reforça o colchão e antecipa amortização se o CDI disparar, mas consome o benefício de capital que motivou a estrutura.

Reflexão (25 pts)

O excess spread cobre o quê ao mesmo tempo?

O risco de base (CDI) e as perdas de crédito — as duas brigam pelo mesmo colchão; o pior caso é CDI e inadimplência subindo juntos ✓
Apenas o risco de base
Apenas as perdas de crédito
Nada — o sênior cobre tudo
Correto. A subordinada retida pelo banco acumula três papéis: skin in the game para a venda definitiva, absorção da inadimplência e absorção do descasamento de indexador. Como base e perdas consomem o mesmo excess spread, o estresse crítico é a alta simultânea de CDI e inadimplência.
